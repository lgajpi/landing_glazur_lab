# Бэкенд заявок Glazur Lab

Простой одностраничный сервис на Go (только стандартная библиотека). Принимает
заявки с формы лендинга и публикует их в чат MAX-бота с кнопками
«Связались / Не связались». Нажатия кнопок сервис слушает сам через long-polling
и обновляет статус прямо в сообщении заявки.

## Эндпоинты

- `POST /api/order` — создать заявку. Тело JSON:
  ```json
  { "name": "Аня", "phone": "+79001234567", "wish": "Роза", "message": "к 8 марта" }
  ```
  Ответ: `200 {"ok": true}` либо `422 {"error": "..."}` при невалидных данных.
- `GET /healthz` — проверка живости.

## Валидация

- `name` — обязательно, до 100 символов.
- `phone` — обязательно, нормализуется к `+7XXXXXXXXXX` (принимает `8…`, `7…`,
  `+7…`, 10-значный номер). Мусор отклоняется.
- `wish` — обязательно (выбранная работа).
- `message` — необязательно, до 1000 символов.

## Переменные окружения

См. `.env.example`:

| Переменная       | Обязательна | Описание                                   |
|------------------|-------------|--------------------------------------------|
| `MAX_BOT_TOKEN`  | да          | Токен MAX-бота (секрет).                    |
| `MAX_CHAT_ID`    | да          | ID группового чата для заявок.              |
| `PORT`           | нет (8080)  | Порт HTTP-сервера (локально ставим 8085).   |
| `ALLOWED_ORIGIN` | нет (`*`)   | Домен лендинга для CORS.                     |
| `SMARTCAPTCHA_SERVER_KEY` | нет | Secret-ключ Yandex SmartCaptcha. Пусто → проверка выключена. |

## Защита от спама (Yandex SmartCaptcha)

Фронт получает одноразовый токен капчи и шлёт его в поле `captchaToken`. Бэк
перед отправкой в MAX подтверждает токен у Яндекса
(`POST https://smartcaptcha.yandexcloud.net/validate`) своим secret-ключом.
При `status != ok` → `403`, в MAX ничего не уходит. Если ключ не задан — шаг
пропускается. Если сервис капчи недоступен — fail-open (пропускаем), чтобы не
терять реальных клиентов. Клиентский ключ (`ysc1_...`) — публичный, в `script.js`.

## Запуск

```bash
cd backend
cp .env.example .env      # заполнить MAX_BOT_TOKEN и MAX_CHAT_ID
go run .                  # .env подхватывается автоматически (godotenv)
```

`.env` читается через `github.com/joho/godotenv` — ручной `source` не нужен.
Переменные, уже заданные в окружении, приоритетнее файла.

Продакшн-сборка:

```bash
go build -o glazur-orders .
MAX_BOT_TOKEN=… MAX_CHAT_ID=… ALLOWED_ORIGIN=https://ваш-домен ./glazur-orders
```

## Как получить токен и chat_id

1. В MAX напишите системному боту **@MasterBot** → создайте бота → получите токен.
2. Добавьте бота в нужный групповой чат.
3. `chat_id` бот видит в поле `recipient.chat_id` любого апдейта из чата, либо
   через `curl -s https://platform-api.max.ru/chats -H "Authorization: ТОКЕН"`.

> Авторизация MAX: токен передаётся заголовком `Authorization: <токен>` —
> **без** префикса `Bearer` (иначе «Malformed access token»). Query-параметр
> `access_token` задепрекейчен. Базовый домен — `platform-api.max.ru`
> (старый `botapi.max.ru` работает до 1 октября).

## Подключение фронта

В `script.js` задайте `ORDER_ENDPOINT` на адрес этого сервиса, например
`https://api.ваш-домен/api/order`. В деплое поставьте сервис за HTTPS-прокси
(nginx/Caddy) и выставьте `ALLOWED_ORIGIN` в домен лендинга.
